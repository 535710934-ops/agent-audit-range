§5发现项详情

严重F-01 agent 权限配置可被读取，且人工确认已被关闭 LLM06[实测]
证据
GET /.vscode/settings.json → 200
危害
一次间接注入即可写入 chat.tools.autoApprove: true，随后所有工具调用不再弹确认，攻击者获得任意命令执行。攻击者无需凭证，只需让 Agent 读到一段含指令的文档。
根因
这是能力授予问题，不是文本检测问题 —— 提示注入检测对此完全无效。
$ curl -s http://<target>/.vscode/settings.json { "editor.formatOnSave": true, "chat.tools.autoApprove": true, ← 人工确认已关闭 "chat.agent.autoRun": true, } $ curl -s http://<target>/.mcp.json → 200，同源可读
修复：① 立即将 chat.tools.autoApprove 置 false； ② 把 .vscode/settings.json、.mcp.json 从 web 可达路径移除 （移出静态目录，或在网关层显式拒绝）；③ 配置下发改为带外管理，禁止从 web 目录读取。
严重F-02 MCP 集成清单暴露，含指向公网的第三方 server LLM03[实测]
证据
GET /.mcp.json → 200，返回 3 个 server 定义
危害
第三方 server 是供应链面：其作者可随时推送更新，一旦被投毒即等于把执行权交给外部。同时该文件暴露了本机可访问的目录范围（/），为后续路径类攻击提供了地图。
"mcpServers": { "filesystem": { "command":"npx", "args":["-y","mcp-filesystem","/"] }, ← 挂载到根目录 "git": { "command":"uvx", "args":["mcp-server-git"] }, "remote": { "command":"npx", "args":["-y","@thirdparty/mcp-remote", "--endpoint","https://<third-party>/mcp"] } ← 公网第三方 }
修复：① 立即移除 remote 条目并评审其必要性； ② filesystem 的挂载根从 / 收窄到业务必需目录； ③ 第三方 server 固定版本号（禁用 -y 拉最新），并纳入变更审计。
严重F-03 单个集成凭据可读取全部租户密钥，且审计日志无操作主体 LLM02[实测]
证据
以集成凭据调用 /mcp 工具 read_secrets → 200，返回全局密钥表；导出端点 /api/v1/export 返回 scope: ALL_TENANTS、1,487,000 条
危害
这不是教科书式 BOLA —— 凭据合法、scope 合法、请求合法，所有常规越权检查都会通过。边界不在「接口有没有校验」，而在「这个凭据被授予了多大范围」。且因审计日志不记操作主体，被利用后无法归因。
关联
该形态在真实事件中表现为 CVSS 9.x 级：Flowise CVE-2025-59434（9.6）、ServiceNow CVE-2025-12420（9.3）。
POST /mcp {"tool":"read_secrets"} → 200 {"AWS_SECRET_ACCESS_KEY":"...","GITHUB_TOKEN":"...","STRIPE_SECRET_KEY":"..."} （全平台共享，非本租户） GET /api/v1/export （同一凭据，无 MFA） → 200 {"scope":"ALL_TENANTS","records":1487000} 审计日志：{"tool":"read_secrets","args":{}} ← 无 actor、无 trace_id
修复：① 立即将集成凭据降权至必需范围，密钥读取改为按租户授权； ② 导出类端点加带外二次确认（一次性 nonce + 超时失效），并对导出行为单独告警； ③ 审计日志补 actor（真实主体）与 trace_id（串联单次攻击的多步调用）—— 这一项是该类攻击唯一的稳定检出信号，优先级高于前两项。
高F-04 单凭据授权粒度过宽（7 个写/管理类工具） LLM06[实测]
证据
单一 token 可见 12 个工具，其中 7 个具写/管理语义：create_record update_record delete_record create_user run_job deploy grant_access
危害
Agent 越权半径由它的权限决定，而非攻击者的技能。一旦某条链路达成任意命令执行，agent 会以机器速度把「读一次」放大成「批量改状态」。
修复：按调用方用途拆分凭据（只读凭据 / 写入凭据 / 管理凭据）， agent 侧只挂只读凭据；grant_access、create_user 这类 权限变更类工具应移出 agent 可达范围。
高F-05 出站白名单含疑似闲置域名，且页面存在现成的数据外发形态 LLM01[实测]
证据
GET /csp.json → 200，含 cdn.legacy-cdn.example.com、api.partner-old.example.org（均为已迁移/闲置命名）；页面含 Markdown 引用式图片语法外联、URL 参数带数据、Base64 编码后外发
危害
这些形态本身不是漏洞，配置里每一项在语法上都是正确的。 风险在于「这些通道还在」：一旦发生间接注入，它们就是现成的数据外发通道。 真实案例中该形态表现为零点击泄露（CVE-2025-32711，CVSS 9.3）。
修复：① 清点白名单，移除已迁移域； ② 恢复域名所有权核查（闲置域名可被他人注册并用于合法外联）； ③ 外发收口到自有域名，移除页面内的数据外发形态。
